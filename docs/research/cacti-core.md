# Cacti core behavior

Research for [#25](https://github.com/somethingwithproof/plugin_pfs/issues/25), run 2026-11-15. Question: does each Cacti function, hook, table, and behavior the plan names hold at `release/1.2.31` and on the current `1.2.x` branch, and which INFO capability declaration makes the reader and the script server input run on a remote collector?

**Result.** Every named function has the same signature at both refs and every named hook is called by core with the arguments recorded below. Four plan statements were wrong or imprecise and are corrected in the plan: Maint's `is_device_in_maintenance` hook has no caller (Thold and core call `plugin_maint_check_cacti_host()` directly); the plan's capability line needs `remote_poller:1` beside `remote_collect:1`, and that was checked by running Cacti's own gating code (below); a device template has no availability setting; and hook and realm registration only works from a function whose name contains `install`, `upgrade`, or `setup`. Most of the facts here were re-checked from the findings of the plugin_cloud research ([cacti-core.md](https://github.com/somethingwithproof/plugin_cloud/blob/main/docs/research/cacti-core.md)) against the pinned refs; the entries say so. Nothing was run on a live Cacti poller, so collector behavior on a real remote poller is marked *live*.

## Method

Rows were read from source with `git show`, `git grep`, and `git rev-parse` on read-only refs of a local Cacti clone (no checkout, no write). One behavior was executed offline: the capability gating functions from `lib/plugins.php` were extracted and run with stubbed globals and temporary INFO files ([tests/capability-gating](../../tests/capability-gating/run.php)). Thold and Maint were read from GitHub at pinned commits.

## Plan corrections

Applied to `docs/PLAN.md` revision 2. Each is listed here with its basis.

1. Plugin metadata paragraph: the declaration is `remote_collect:1, remote_poller:1` (confirmed by the capability gating run), not an assumption to test. Remaining live check: the same on a real collector.
2. Compatibility, plugin lifecycle bullet: add that `api_plugin_register_hook()` and `api_plugin_register_realm()` must be called from a function whose name contains `install`, `upgrade`, or `setup`; and that `api_plugin_db_table_create()` is a no-op for an existing table on 1.2.31 but refreshes the schema on `1.2.x`.
3. Compatibility, background work bullet: `exec_background()` takes one executable path plus an argument list; `exec_background_process()` exists only on `1.2.x`.
4. Upstream behavior, Cacti core table: replace the Thold/Maint row consequence with the Maint finding above; add rows for reindex methods and orphan handling, script call counts, `remote_agent` authorization at both refs, and the table-name length limit.
5. Cacti objects: a device template has no availability setting; set `availability_method` 0 through `api_device_save()`.
6. Cacti objects, data query: the data query's index steps run as a CLI process, so the script needs a CLI entry point.
