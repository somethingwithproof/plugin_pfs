<a id="operator-guide"></a>
# 操作员指南

如何安装、运行、升级、备份和移除插件，以及其图表和值的含义。节点准备见 [node-setup.md](node-setup.md)；使用 Thold 和 Maint 告警见 [alerting.md](alerting.md)。

状态：阶段 1 代码完成，仅在一次性 Cacti 中使用节点输出样本运行过。尚无真实 Lustre 文件系统试点报告（[#57](https://github.com/somethingwithproof/plugin_pfs/issues/57)）；在有报告之前，请将下文所有数字视为测试样本结果。

<a id="requirements"></a>
## 要求

| 组件 | 要求 |
|---|---|
| Cacti | 1.2.31 或更高，无需核心补丁 |
| PHP | 所有运行 Web 界面或轮询器的 Cacti 主机均需 8.2 或更高。PHP 8.0 或 8.1 时插件拒绝启用，Cacti 继续工作 |
| Lustre | 通过 SSH 强制命令读取脚本访问服务器；已从源码检查的版本为 2.15.8、2.16.1 和 2.17.0 |
| 轮询器主机 | `ssh` 客户端、读取器私钥及已知主机文件 |

<a id="install"></a>
## 安装

1. 解压发布包，使插件目录为 `<path_cacti>/plugins/pfs`。目录必须名为 `pfs`；GitHub 源码包解压为 `plugin_pfs-<version>`，必须重命名。
2. 在 Cacti 打开配置、插件，安装并启用并行文件系统。安装创建插件表、注册钩子及三个权限域、导入设备/数据/图表模板，并将两个数据查询文件复制到 Cacti（见下一节）。
3. 在用户管理中授予所需权限域：**Parallel Filesystem View** 用于清单和新鲜度，**Parallel Filesystem Operator** 用于操作页面和个人分诊确认，**Parallel Filesystem Admin** 用于注册表和健康页面。每次请求中 Admin 继承 Operator 访问权，Operator 继承 View 访问权，不增加持久授权。三者均遵循 Cacti 设备权限。
4. 打开控制台、并行文件系统健康。每条警告都说明要修复的内容。新安装通常显示缺少 SSH 密钥和已知主机文件，直到完成后续步骤。
5. 按 [node-setup.md](node-setup.md) 准备节点和轮询器。
6. 在并行文件系统管理中，允许每个轮询器可访问的网络，添加文件系统，再添加节点（端点、端口、登录名、角色）。端点解析到允许网络之外的节点不会保存。
7. 等待一个轮询间隔。读取器由各轮询器上的 Cacti `poller_bottom` 钩子运行，填充清单。在文件系统页面审查建议目标；忽略的目标会从数据查询和汇总中移除。
8. 从管理页面创建文件系统设备（或映射到现有设备）。插件先列出将添加的内容，再执行：设备、两个数据查询及五个概览图表。逐目标图表可在 Cacti 新建图表页面按需创建。

<a id="data-query-files"></a>
### 数据查询文件

Cacti 只读取 `<path_cacti>/resource` 内的数据查询 XML，因此安装将插件中的 `resource/script_server/pfs_osts.xml` 和 `pfs_mdts.xml` 复制到 `<path_cacti>/resource/script_server/`。目标任一处为符号链接时会拒绝，并通过同目录临时文件写入每个文件。它只记录自己写入文件的 SHA-256：已存在且内容相同的文件（例如按下列步骤手动复制）会被使用，但仍归您所有，卸载会保留。安装绝不替换非自身写入或后来被修改的文件，卸载仅移除自身写入且未修改的文件。

如果 Web 服务器用户不能写该目录，健康页面会说明，数据查询也无法列出目标。由有权限的用户复制一次文件，保持 Web 服务器和轮询器用户可读：

```sh
cd <path_cacti>
install -m 0644 plugins/pfs/resource/script_server/pfs_osts.xml resource/script_server/
install -m 0644 plugins/pfs/resource/script_server/pfs_mdts.xml resource/script_server/
```

然后在健康页面使用 **重新安装模板**。两个副本与插件一致时警告清除。由于这些副本归您所有，插件不更新也不移除：升级改变任一文件后请重新复制（不同时健康页面会警告），卸载后自行删除。

<a id="what-the-graphs-and-values-mean"></a>
## 图表和值的含义

每个文件系统是一个 Cacti 设备。其目标（OST 和 MDT）是两个脚本服务器数据查询的索引。所有值来自读取器缓存；图表、页面或数据源均不联系节点。

| 图表 | 值 | 何时未知 |
|---|---|---|
| 填充（概览） | OST 已用百分比最大值、平均值、最小值及差值（最大减最小），目标总数、缺失数和不健康数 | 没有 OST 具备当前容量读取 |
| 容量（概览） | 文件系统总量和可用千字节 | 任意 OST 缺失或过期，导致总量不完整 |
| 吞吐量（概览） | 文件系统每秒读写字节，以及用于告警的读写速率 gauge（显示在图表下方） | 任意 OST 缺失、过期、不健康且没有计数器，或在间隔内重置；速率 gauge 在重置后的一至两次轮询中也未知 |
| 元数据（概览） | 文件系统每秒元数据操作，所有允许操作合计，以及用于告警的操作速率 gauge | 任意 MDT 缺失、过期或在间隔内重置；速率 gauge 在重置后的一至两次轮询中也未知 |
| 数据年龄（概览） | 汇总最旧观测以来的秒数及贡献目标计数 | 从未观测 |
| OST 容量、Inode、吞吐量（逐目标） | 已用和可用、inode、每秒读写字节及每秒操作 | 目标缺失、过期或节点未输出该值 |
| MDT 容量、操作（逐目标） | 已用和可用、inode、按操作分类的每秒速率 | 同上 |

表格背后的规则：

- **已用百分比** 遵循 `lfs df`：已用除以已用加可用，向上取整。
- **未知是缺口，绝不是零。** 缺失目标、读取失败或节点未输出的值均绘制为缺口。
- **计数器** 以原始值存为 DERIVE，最小值 0。重置（下降、`start_time` 变化、故障转移后另一节点响应或上一值未知）恰好使一个间隔未知。
- **新鲜度。** 年龄不超过一个半间隔为当前，最多三个间隔为延迟，之后为过期。Gauge 在当前或延迟时提供；计数器和汇总速率 gauge 仅在当前时提供，因此漏读是缺口，而非先平线再双倍速率。
- **空闲目标。** Lustre 不输出自开始时间以来从未计数的计数器。对于存在、在服务中且本次读取报告了其他值的目标，文件系统求和将其视为零；逐目标图表仍显示缺口（[ADR 0013](../../../decisions/0013-absent-counter-lines-count-as-zero-in-sums.md)）。
- **目标集合变化。** 当目标加入或离开求和集合时，该和在一次轮询中未知，以免将整个历史绘制为一个间隔。
- **缺失目标** 保留索引、数据源和历史，直到管理员在注册表中忽略它们。

<a id="upgrade"></a>
## 升级

1. 先备份（见下文）。
2. 用新版本替换 `plugins/pfs` 目录，保持目录名。
3. 打开配置、插件。Cacti 显示新版本；下次加载配置时（打开插件页面就会加载），插件更新数据库结构、钩子、权限域、模板及数据查询文件。中断的升级会在下次加载时完成。结构版本落后时读取器不运行，并记录必须完成升级。
4. 如果从尚无速率 gauge 的预发布版本升级，请先保留所需的吞吐量和元数据图表历史，再删除并重建这些概览图表。其现有 RRD 文件不包含新的速率数据源。
5. 检查健康页面和 Cacti 日志。模板或查询文件问题会报告，不会静默跳过。

当数据库结构比代码新时，拒绝降级至旧插件版本；应恢复升级前的备份。

<a id="back-up-and-restore"></a>
## 备份和恢复

在同一时刻一起备份下列内容：

| 内容 | 位置 |
|---|---|
| 插件表 | Cacti 数据库中所有 `plugin_pfs_*` 表（`mysqldump cacti $(mysql -N -e "SHOW TABLES LIKE 'plugin\_pfs\_%'" cacti)`），或整个 Cacti 数据库 |
| Cacti 对象 | Cacti 数据库：文件系统设备、其数据源和图表、模板及 `settings` 中的插件设置（`pfs_*`） |
| RRD 文件 | `<path_cacti>/rra` 或您的 RRD 目录 |
| 节点访问 | 每个轮询器上插件设置指定的 SSH 密钥和已知主机文件。每个节点上的读取器账户、其 `authorized_keys` 行及 `/usr/local/libexec/pfs-read.sh` |
| 查询文件副本 | 手动复制时的 `<path_cacti>/resource/script_server/pfs_osts.xml` 和 `pfs_mdts.xml` |

恢复时，停止轮询器，从同一备份恢复数据库及 RRD 目录，恢复密钥和已知主机文件，然后启动轮询器。读取器下次运行会继续，不创建重复数据源：设备、数据源及 RRD 文件按存储的 ID 和路径匹配。恢复后第一次轮询绘制一个未知计数器间隔，因为读取器无法信任跨缺口速率。如果恢复的结构比安装代码旧，插件会检测并按升级步骤更新。恢复由 `tests/bin/restore-flow.php` 验证。

<a id="uninstall"></a>
## 卸载

1. 可选：从并行文件系统管理导出注册表。
2. 在配置、插件中先禁用再卸载。
3. 卸载移除插件钩子、权限域及自身写入且未修改的数据查询文件副本。移除 `poller_bottom` 钩子会停止读取器，因此卸载后不再采集节点值：现有图表保留历史但停止更新，最新值变未知。导入的模板像其他导入模板一样留在 Cacti。默认勾选 **卸载时保留插件表** 时表保留；取消则删除。
   - **设备。** 默认保留每个设备及其数据源和图表。在配置、设置、并行文件系统中勾选 **卸载时删除此插件创建的设备**（默认关闭），卸载便会通过 Cacti 自身的设备删除功能删除插件从管理页面创建的设备：其图表和数据源随之删除，RRD 文件仅在 Cacti 的 RRD 清理设置要求时删除。插件在 `plugin_pfs_created_devices` 中记录自己创建的每个设备，每设备一行；映射到文件系统的现有设备绝不进入此记录，始终保留，包括映射添加的数据查询和概览图表。设备删除后，文件系统不再保留其映射，因此保留的表不会指向已删除设备。即使卸载删除插件表，只要 `plugin_pfs_created_devices` 仍列有 Cacti 中存在的设备，该表就会保留，使以后重新安装和卸载时仍能删除它们；如果永久保留这些设备，请手动删除该表。您自行创建的设备、数据源、图表和 RRD 文件由您自行移除。
4. 在每个节点移除读取器的 `authorized_keys` 行、读取脚本及账户。卸载绝不联系存储节点。

<a id="troubleshooting"></a>
## 故障排除

先查看健康页面，它指出节点、轮询器及原因；然后查看按 `PFS` 筛选的 Cacti 日志。

| 症状 | 原因与修复 |
|---|---|
| 节点显示“主机密钥不在已知主机文件中，或已变化” | 使用与注册完全一致的端点名添加或修正密钥。信任变更密钥前通过独立渠道验证；读取器绝不自行接受 |
| “响应没有固定读取脚本边界标记” | 密钥未限制到强制命令，或命令并非 `pfs-read.sh`。修复 `authorized_keys` 行 |
| “输出了插件不读取的 N 个参数” | 节点运行的不是随附脚本。重新安装 `node/pfs-read.sh` |
| “解析到允许网络之外” | 在管理页面允许该轮询器访问的网络，或修正端点 |
| 节点读取被记录为失败或部分完成 | 无法访问、超时或响应超过 **最大响应**。目标保留上次值直到过期，然后变未知 |
| “轮询器 N 上的读取器尚未完成运行” | 轮询器未运行 `poller_bottom`、其 PHP 低于 8.2，或 Cacti 的 **PHP 二进制路径** 为空。日志指出具体原因 |
| 数据查询没有列出目标 | 查询文件副本缺失或不同（见数据查询文件），或读取器尚未完成读取 |
| 逐目标图表上的计数器始终缺口 | 读取器账户无法读 OST `stats`。Lustre 2.17 将其放在 debugfs（[node-setup.md](node-setup.md)） |
| 文件系统吞吐量缺口，但逐目标吞吐量有图线 | 某目标缺失、过期、不健康或刚重置；填充图上的缺失及不健康目标计数说明情况 |
| 概览图表已创建但为空 | 设备由另一轮询器采集，而非读取其节点的轮询器；健康页面警告不匹配 |
| 轮询器日志显示 `Plugin 'thold': Uncaught TypeError` 且 Thold 被禁用 | 计数器上的 Thold 阈值遇到未知间隔；删除阈值，在插件页面重新启用 Thold，并参阅 [alerting.md](alerting.md#counters-and-thold-182) |
