# Lustre parameter paths and formats

Research for [#16](https://github.com/somethingwithproof/plugin_pfs/issues/16), run 2026-11-15. Question: does each row of the plan's Lustre facts table hold on Lustre 2.15.x, 2.16.x, and 2.17.x, given that the plan cited source and man pages at tag `v2_17_0` only?

**Result.** The stats line format, the "zero samples are omitted" rule, the clear-on-write behavior, the OFD counter set, and the capacity attributes hold in source at `v2_15_8`, `v2_16_1`, and `v2_17_0`, with these differences that change the design: (1) on 2.17.0 the OST `stats` and `recovery_status` files are created in debugfs, while on 2.15.8 and 2.16.1 they are in procfs, so an unprivileged read of OST counters is likely to fail on 2.17 (kernel debugfs is root-only by default; not tested); (2) the `enable_stats_header` switch exists from 2.16.1, and on 2.15.8 the `start_time` and `elapsed_time` lines are always printed; (3) the MDT counter name list grows from 2.15.8 to 2.16.1 and 2.17.0; (4) the target condition parameters differ per release (`no_create` from 2.16.1, `readonly` and `statfs_state` only on 2.17.0, and `lfs df` flag `N` is "no-precreate" before 2.17); (5) the man pages the plan said were absent before 2.17 are present at `lustre/doc/` in the 2.15.8 and 2.16.1 tags. Nothing here was run on a Lustre node, so every behavior that needs a server (what a given user can read, what a real stats file looks like, fixtures) is marked *live*, and the exit criterion "fixtures for every matrix release" is not met.

## Method

Read the Lustre source at three tags through the GitHub API, saved to a scratch directory outside the repository, and compared the same function at each tag. The man pages come from the same tags. No Lustre node, no `lctl`, and no credentials were used.

## Limits

- Everything is from source. No stats file, `lfs df` output, or directory listing from a real node was seen, and the reading of "stats is in procfs" or "in debugfs" is from the registration code, not from a mounted node. The unit string for each type was read at 2.17.0 only.
- Which parameters each node type (OSS, MDS, combined, client) exposes, and ZFS-backed specifics, were not read per OSD beyond `dt_def_attrs`.
- The effect of the `obd_enable_stats_header` switch default on distribution kernels was not checked.
